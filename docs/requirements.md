# Table2Map 首版需求

## 目标与边界

Table2Map 是供团队浏览地点 POI 的移动端优先网站。飞书多维表格是首版唯一的内容维护入口；网站不提供创建、编辑或删除 POI 的功能。

访问控制由外部系统负责，应用本身不实现登录、用户、权限或后台管理功能。

首版覆盖中国大陆和香港，使用 Leaflet 渲染交互地图，天地图提供底图，并部署在 Vercel 的 Next.js 应用中。

## 信息架构

- 首页：搜索、筛选、POI 卡片列表和交互地图。
- POI 选择状态：使用首页 URL 参数 `?poi=记录 ID` 分享；打开链接后定位并高亮对应标记。
- 移动端：地图在上，搜索、标签筛选和地点列表在下。

首屏根据全部已发布 POI 的范围调整地图视野；没有已发布 POI 时显示空状态。

## 飞书数据契约

飞书多维表格为唯一数据源。服务端仅读取状态值严格等于 `已发布` 的记录。

首版字段映射由集中配置管理，页面和地图只使用内部 POI 模型。这样可更改飞书字段名，也可增添字段而不改动核心交互逻辑。

| 内部属性   | 飞书字段 | 类型与用途                                           |
| ---------- | -------- | ---------------------------------------------------- |
| `name`     | 位置     | 使用位置字段的可读文本作为 POI 名称                  |
| `location` | 位置     | 系统地理位置字段，提供省、市、区、经纬度及格式化地址 |
| `status`   | 状态     | 仅 `已发布` 的记录可见                               |
| `type`     | 类型     | 单选，用于展示与筛选                                 |
| `review`   | 评价     | 飞书 Object 字段中的可读摘要；若接口未返回则不展示   |
| `rating`   | 评分     | 飞书评分字段，范围 1–5                               |
| `images`   | 图片     | 飞书附件字段；首图用于卡片缩略图与地图弹卡封面       |

位置、类型、状态、评价、评分和图片均允许在映射配置中改绑到实际的飞书字段。后续字段作为详情扩展项加入，不改变上述基础契约。

## 坐标与地图

- 输入坐标默认视为 GCJ-02。
- 地图适配层负责按天地图底图的实际坐标要求转换坐标；业务组件不直接处理坐标系。
- 接入真实数据时，必须用一条深圳记录和一条香港记录做视觉验收，确认标记与真实地点重合。若偏移，以验收结果调整坐标适配层，而不是修改飞书原始数据。
- 地图标记与卡片双向联动：点击卡片定位、高亮并打开弹卡；点击标记同步更新选中状态和分享 URL。
- 当点位数量增长到影响可读性时，启用标记聚合。

## 发现与筛选

- 名称关键词搜索，匹配位置字段文本。
- 类型单选筛选。
- 城市单选筛选。
- 筛选结果同时影响卡片列表、地图标记和结果数。
- 首版不包含路线规划、收藏、评论、投稿或多选类型筛选。

## 技术决策

- Next.js 16 Active LTS 的 App Router + TypeScript。项目初始化时锁定当日最新的 16.x LTS 补丁；以本需求确认日为基线是 16.3.8。
- React 19 的最新稳定小版本；以本需求确认日为基线是 19.3。不得使用 RC、canary 或实验性 React API。
- 以 Server Components 在服务端请求飞书，地图和筛选交互作为 Client Components；飞书应用凭据不得下发给浏览器。
- Tailwind CSS 负责界面布局与样式；仅对 Leaflet 运行时生成的弹卡补充少量全局 CSS，不引入额外组件库。
- Leaflet 1.9.4（其官方标示的最新稳定版）+ 天地图 WMTS/REST 瓦片服务；保留必要的地图数据来源归属。首版不使用无人维护的地图 React 封装层。
- 飞书 API 结果先标准化、校验和过滤，再提供给 UI。

### 服务接口方案

- 飞书：使用开放平台的 Bitable v1 服务端记录列表接口及 `tenant_access_token`。完整处理分页，只请求所需字段；不使用浏览器端飞书 SDK、Base Extension API 或非官方封装。
- 天地图：只使用 HTTPS 瓦片接口，不使用天地图 JavaScript SDK。瓦片 Key 属于浏览器必需参数，应使用仅授予瓦片服务、并在天地图控制台限制来源域名和配额的 Key；飞书凭据与任何可写服务凭据始终只保存在 Vercel 服务端环境变量中。
- 图片：飞书附件在服务端解析，并通过受控的应用图片响应提供给 `next/image`；不把飞书访问令牌、原始附件授权参数或记录 API 直接交给浏览器。

## 缓存与可用性

首版使用 Next.js 已稳定的 `fetch`/ISR 缓存接口，明确设置 5 分钟重验证和 `pois` 缓存标签。数据缓存到期后的首个访问可获得旧内容，同时触发后台更新；刷新失败时保留上一份成功数据，避免飞书 API 短暂异常导致页面不可用。不依赖 Cache Components、PPR 或其他仍带实验性标记的能力。

后续如需发布后即时可见，可增加由飞书自动化调用的、带密钥校验的 Route Handler，并用稳定的路径/标签失效接口刷新 POI 缓存；这不引入终端用户鉴权。

## 版本与维护策略

- 使用 `pnpm` 和提交的 lockfile，生产构建只使用锁定版本，禁止在构建步骤中安装 `latest`。
- 依赖按月检查，并在 Next.js、React、飞书 API 或天地图出现安全公告时优先升级；始终留在 Next.js Active LTS 支持线。
- 升级遵循官方迁移指南，先在预览部署验证 POI 列表、筛选、地图定位、图片和缓存，再发布生产环境。
- 每次升级前确认 Leaflet 及实际引入依赖均声明支持当前 React 版本；不以 `--force` 或 `--legacy-peer-deps` 绕过不兼容的 peer dependency。

## 首版验收

1. 只有飞书中状态为 `已发布` 的记录被展示。
2. 一条深圳记录与一条香港记录在天地图上位置正确。
3. 名称、类型和城市筛选都同时更新列表和地图。
4. `?poi=记录 ID` 可分享选中地点；弹卡显示类型、评分、位置、评价和首图（如有）。
5. 典型手机宽度下，筛选、列表和地图操作均可完成。
6. 飞书数据短暂不可用时，已有缓存仍可正常浏览。
